## Config Usage

The committed `config.example.toml` is observe-only and contains no raw credentials.

```bash
arb-agent --config config.example.toml
```

Secret configuration must use references only, such as environment variable names or local keystore aliases. Local keystore loading uses versioned authenticated encryption for test/local entries, local rotation planning records only alias cutover metadata without writing entries or revoking credentials, local keystore preflight validates alias entry metadata without loading material or decrypting plaintext, and `arb-agent validate-secret-boundary-audit --workspace <fresh-dir>` replays local rotation-plan audit/checkpoint records without secret side effects. Raw API keys, wallet keys, seed phrases, mnemonics, and tokens are forbidden in repository files.

## Phase 19 Runtime Lifecycle Boundary

The runtime lifecycle boundary wires local audit/state preconditions around deterministic adapter evaluation. It appends audit events, checkpoints the plan before adapter evaluation, evaluates the deterministic adapter boundary, checkpoints the adapter run, and records that no external submission or live execution occurred. It has a local concurrent lifecycle test over shared audit journal and SQLite WAL state paths, a simulated state-permission failure test that stops before adapter evaluation, a standalone `arb-agent validate-runtime-permission-denial --workspace <fresh-dir>` CLI gate for local state-write fail-closed validation, a local graceful-shutdown checkpoint boundary that writes shutdown audit records and a SQLite-reopenable state checkpoint without stopping services, a standalone `arb-agent validate-runtime-graceful-shutdown --workspace <fresh-dir>` CLI gate for local checkpoint/reopen verification, a local backup-restore validation that copies non-secret audit/SQLite artifacts and verifies restored runtime checkpoints, a standalone `arb-agent validate-runtime-backup-restore --workspace <fresh-dir>` CLI gate for local lifecycle artifact copy/reopen validation, a standalone `arb-agent validate-runtime-backup-restore-load --workspace <fresh-dir>` CLI gate that runs concurrent local lifecycle workers before backup/restore replay, a local restart recovery summary that replays audit plus SQLite checkpoints without service resume and carries recovered opportunity-trace summaries, a standalone `arb-agent validate-runtime-restart-recovery --workspace <fresh-dir>` CLI gate for local restart-recovery replay/reopen validation, a standalone `arb-agent validate-runtime-incomplete-recovery --workspace <fresh-dir>` CLI gate for missing-checkpoint fail-closed validation, a local process-supervised `arb-agent validate-runtime-supervised-restart --workspace <fresh-dir>` gate that writes lifecycle checkpoints in a child process and reopens them in the parent, and a local deployment-like smoke harness plus `validate-runtime-smoke` CLI runner that combine lifecycle, graceful-shutdown, backup/restore, restart recovery, opportunity-trace summary accounting, and audit durability probes without service-manager actions. It rejects live-scope lifecycle requests before audit/state mutation. This is local lifecycle wiring only, not production deployment or live execution readiness.

## Phase 21 Paper Balance Ledger Boundary

The paper balance ledger boundary tracks local simulated balances only. ## Phase 22 Crash/Restart Durability Boundary

The crash/restart durability boundary is a local Cargo integration harness. It starts child test processes that write SQLite WAL checkpoints and exit abruptly after start, planner, or adapter stages; the parent process reopens the database, runs integrity checks, and verifies expected checkpoint recovery. It does not simulate power loss, disk-full behavior, deployment services, live trading, real venues, signing, broadcasts, withdrawals, bridges, custody, or production readiness.
